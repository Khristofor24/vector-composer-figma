# ADR 0004 — Раздельные public и private demo пакеты

## Контекст
Пользователь разрешает временный встроенный ключ только для приватного демопакета и сам отзывает его. Исходники и сборка для репозитория должны оставаться без ключа.

## Решение
Создаём независимые public и private demo выходы. Встраиваем временный ключ только при приватной сборке из локального игнорируемого файла; пользователь вводит его локально без вывода значения. Собственный ключ имеет приоритет и живёт только в памяти запуска. После очистки собственного ключа демонстрационный не включается неожиданно: переход на него явный. Исходный архив собираем по разрешённому списку, public сборку проверяем на отсутствие ключа.

## Почему
Единый пакет с ключом нарушает разделение R33–R34. Хранение личного ключа в настройках Figma, метаданных, логах или экспорте нарушает R31. Автоматический отзыв противоречит выбранному ручному отзыву; публикация и отправка требуют отдельного согласования пользователя.

## Последствия
Приватный пакет содержит секрет и передаётся отдельно от public материалов. После отзыва пользователь может ввести свой ключ, а существующая композиция остаётся доступной. Подготовленный сборщик не означает проверенный private demo: нужен локально внесённый ключ и настоящий запрос.
