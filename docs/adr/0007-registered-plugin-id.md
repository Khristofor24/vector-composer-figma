# ADR 0007 — D01: зарегистрированный ID для private pluginData

## Контекст
Реальная проверка в Figma Desktop выявляет отказ setPluginData без ID плагина. Ранний импорт книги без метаданных подтверждает только импорт SVG, а не сохранение и повторное открытие композиции по R02/R19/R44.

## Решение
Используем настоящий ID, выданный Figma через Development → New plugin: пользователь создаёт локальный регистрационный template, из которого берём только публичный manifest.id. Сохраняем один и тот же ID в исходном manifest и выходах public/demo. Сборка явно отказывает при отсутствии ID до передачи пакета и AI-проверки. Метаданные сцены остаются private pluginData.

## Почему
Выдуманный или чужой ID не подтверждает регистрацию этого плагина и запрещён D01. Удаление persistence либо обход через shared data нарушает принятое решение и требование продолжать работу с композицией. Успешный SVG-импорт без ID не заменяет проверку private pluginData в Desktop.

## Последствия
Подготовка сборки зависит от регистрационного template, созданного пользователем; само значение ID в ADR не фиксируется. Public и demo сохраняют общую идентичность плагина. Проверка наличия ID при сборке выявляет отсутствие конфигурации заранее, но сохранение и повторное открытие требуют настоящей Desktop-проверки; ранний импорт не считается её результатом.
