# Происхождение SVG-каталога

Включены десять типов предметов: книга, смартфон, пазл, монета, наушники, лампа, цветы, кошелёк, папка и ручка. Каждый имеет версии S/L и главное/фоновое состояние: всего **40 исходных вариантов**. Упоминание «20 иллюстраций» в задании не означает наличие двадцати отдельных файлов: фактически предоставлены два библиотечных листа с десятью главными и десятью фоновыми предметами на каждом. Недостающие предметы не генерировались.

Оригинальные файлы в корне и пользовательских папках не изменены. Их точные копии находятся в `assets/source/`, чтобы чистый checkout содержал всё необходимое для воспроизводимой проверки. SHA-256 всех 11 исходников записаны в `assets/catalog.json`. Каталог содержит исходные SVG-строки и метаданные; отдельные варианты — `assets/svg/`.

## Извлечение

Команда: `npm run assets` (Python 3.9+ и PyMuPDF 1.26.5; для обычной сборки/работы плагина Python не нужен).

`scripts/extract-assets.py` задаёт отдельную геометрическую область каждого предмета на исходных листах. Берутся **целые исходные SVG-элементы**, все границы которых находятся внутри области. Некоторые мелкие детали предшествуют большому силуэту в XML, поэтому простые последовательные диапазоны были недостаточны и заменены геометрическим выбором.

Атрибуты `d`, исходные заливки, обводки и порядок выбранных элементов сохраняются. Добавляется только внешний контейнер `g transform="translate(...)"`, нормализованный viewBox и отступ 0,5 исходной единицы для защиты сглаживания обводок. Ширина и высота вычисляются по видимым кривым с учётом толщины обводок и включают векторную тень. Геометрия не трассировалась, не перерисовывалась и не растрировалась.

В `assets/provenance.json` для каждого варианта записаны оригинальный файл, точные индексы выбранных XML-элементов, область выбора и исходные bounds. Тесты подтверждают принадлежность всех d оригинальному источнику, отсутствие назначения одного элемента двум предметам, соответствие footprint главной/фоновой версии и неизменность исходников.

## Особенности исходников

- S и L действительно имеют разную детализацию. В S главные смартфон и монета упрощены, но соответствующие фоновые версии в предоставленном листе сохраняют более подробные детали. Эта асимметрия оставлена как в оригинале.
- Цветы L и S не имеют абсолютно того же коэффициента увеличения, что книга; канонические размеры каждого исходного варианта сохраняются, независимого «выравнивания по размеру карточки» не выполнялось.
- Точная третья акцентная краска бирюзовой схемы — `#B6C6FE`. Палитры получены из прямоугольных образцов на обоих листах.
- В исходных предметах присутствуют очень мелкие отдельные контуры. Они сохраняются, если принадлежат области предмета; удалять детали по эстетическим соображениям нельзя.

## Визуальная проверка

Все сорок вариантов отрендерены в `assets/qa/`. Файлы с префиксом `source-` — независимые обрезки соответствующего участка полного исходного листа; файлы без префикса — рендер извлечённого SVG. Листы `contact-S.png` и `contact-L.png` показывают главный вариант слева и фоновый справа. Они просмотрены после исправления исходного диапазонного извлечения: устранены чужая точка у кошелька S и потерянная нижняя деталь монеты L. Извлечённые формы узнаваемы, тени и контуры сохранены. PNG используются только для QA, плагин импортирует SVG.

Ранний native import/export через Figma MCP и настоящая установка плагина в Desktop проверяются оркестратором отдельно; изображения QA и Node tests не заменяют такие проверки.
